## 2. Concrete findings, highest impact first

### A. Intrabar ordering bias — `backtest_runner.py` lines 223–236

Within a single daily bar the code updates the high-water mark from `bar["high"]`, activates the
trailing stop, *then* tests both stops against `bar["low"]`.

This assumes the high always occurred before the low, on every bar. Real bars go both ways.
The effect is systematic and one-directional: trailing-stop exits are over-counted at favourable
prices, stop-loss exits under-counted.

Current DB shows 162 trailing-stop vs 158 stop-loss exits — close enough that this bias could
plausibly flip the ranking.

**Fix options:** assume worst-case ordering (test the hard stop before updating the high), or drive
exit checks off the 4H bars already being fetched rather than the daily bar.

### B. One-sided slippage — `backtest_runner.py` line 322

```python
entry_price = nb.iloc[0]["open"] * SLIPPAGE   # SLIPPAGE = 1.002
```

Slippage is applied on entry only. Exits fill at exactly `stop_loss`, `trailing_stop` or `close`
with no cost. Round-trip friction is therefore understated by roughly half.

Worse: a stop-loss exit assumes a fill *at* the stop price. Gaps through the stop are not modelled,
and gap-downs are where the large losses actually come from.

**Fix:** apply slippage to both legs; on stop exits, fill at `min(stop_price, bar_open)`.

### C. In-sample parameter fitting — `constitution_builder.py` (the big one)

The pipeline is:

1. `backtest_runner.py` generates ~750 trades
2. `constitution_builder.py` reads *those same trades* and picks:
   - `best_score` — the signal score with the highest observed win rate (line 470)
   - `best_stop` — 80th percentile of observed stop hits + 1% (`derive_stop_loss`)
   - `best_hold` — the hold period with the best observed win rate (`derive_best_hold`)
3. Those values are locked into `constitution.json`
4. The live bot runs on them

There is no holdout period and no out-of-sample test. Parameters are chosen by scanning history for
whatever worked in that history. This is the failure mode the video's "Prove or Kill" and
"Luck vs Edge" chapters exist to prevent.

Note also: `backtest_runner.py`'s header calls it a "walk-forward backtesting engine". It is a single
sequential pass with fixed parameters — a forward simulation, not walk-forward validation.
Walk-forward means fit on window N, test on window N+1, roll, and only report the test results.

**Fix:** split the date range. Fit the constitution on the first ~70%, evaluate untouched on the
last ~30%, and report only the out-of-sample numbers. Add a permutation/Monte-Carlo test: shuffle
the trade sequence a few thousand times and check where real expectancy sits in that distribution.

### D. Dead code — per-segment score threshold is never derived

`constitution_builder.derive_segment_rules`, lines 107–115:

```python
score_wins  = defaultdict(int)
score_total = defaultdict(int)
for sc in s["signal_scores"]:
    score_total[sc] += 1

best_score    = default["min_signal_score"]
best_score_wr = 0
```

The comment on the next line says "rebuild wins per score from the trades belonging to this
segment" — but no such loop exists. `score_wins` and `best_score_wr` are written and never read.
`best_score` keeps its default and is written straight into the segment rules at line 140.

So per-segment `min_signal_score` has always been the `config.SEGMENT_RULES` default. The feature
looks implemented in the output and isn't.

### E. Unordered queries used for chronological analysis

`fetch_trades()` has no `ORDER BY`. Two consumers assume row order is chronological:

- `analyse_trajectory` splits rows in half and reports "first half vs second half win rate"
- `analyse_streaks` walks `reversed(pnls)` to count *trailing* consecutive losses

SQLite usually returns rowid order, which usually matches insertion order — but it is not
guaranteed, and `analyse_streaks` also interleaves symbols. Add `ORDER BY entry_date` (and sort
per-symbol in `analyse_streaks`).

## 3. Suggested order of work

1. **Fix D and E.** Unambiguous bugs, no trading judgment involved, low risk.
2. **Fix A and B.** Makes the backtest honest. Expect results to get *worse* — that is the point.
3. **Re-run the backtest.** Compare against the current −$510 / 380-trade record.
4. **Then and only then** add the out-of-sample split (C).
5. Kelly sizing and the macro-news blackout come after there is evidence of an edge to size.

Adding features 5 before fixing 1–4 means sizing a strategy that has not been shown to work.
